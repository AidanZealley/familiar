Everything runs in this page: the real core, in-memory storage, the HTTP and SSE routes, and the client store. Only the model is scripted, so Familiar understands a few phrases. Press **Assistant** in the frame, or open it fullscreen to see the chat beside the board, and try:

- What's in progress?
- Add a task: Write the release notes
- Assign T-3 to me
- Move T-3 to done
- What's on the board?

Then drag a card or press **Assign to me** and ask again. Familiar reads the board as it is now. Reloading resets the demo.

## One owner for the tasks

The board is the only place tasks change. Its UI and Familiar's tools call the same operations, and each tool returns its result as text for the model and as `details` for a UI:

```ts
defineTool({
  name: 'assign_task_to_me',
  description: 'Assigns a task to the person asking.',
  parameters: Type.Object({ taskId }),
  execute: async ({ taskId }, api) =>
    run(() => {
      // The host's authenticated author, never a tool argument.
      if (!api.author) {
        throw new BoardError('Nobody asked, so there is no one to assign.')
      }
      const task = board.assign(taskId, api.author)
      return { text: `Assigned ${describeTask(task)}.`, tasks: [task] }
    }),
})
```

Every board tool is available to everyone in the conversation. `assign_task_to_me` acts only for a person: the author of the message that started the call, or a schedule's creator, never memory upkeep. This board lets anyone change any task. A board with rules about who may change what would check them in its operations, against `api.author`, so the same rules apply to the UI and the tools.

## Only what it needs

The host allows sending, history, aborting and the conversation's event stream. Memory, schedules, sign-in, connections and MCP answer 403:

```ts
const CHAT = new Set<Operation>([
  'conversation.send',
  'conversation.history',
  'conversation.abort',
  'events.conversation',
])

const createHostApi = (familiar: Familiar, author: Author) =>
  createHttpApi(familiar, {
    authenticate: () => author,
    allow: (_, operation) => CHAT.has(operation),
  })

const store = createFamiliarStore(url, { fetch })
```

The demo has one fixed person and nobody signs in, so `authenticate` names them for every request. That is a demo identity, not authentication. In the demo, `fetch` hands each request to the routes inside the page. A real host serves them from its server, authenticates each request from its session and passes the API's URL instead.

## Using a real model

The scripted model is a faux provider registered in the page's `Models`. To use a real one, run the same Familiar on a server you control with a provider from [Models and sign-in](/familiar/build/models-and-sign-in/), and serve the routes as in [Serve the API](/familiar/build/serve-the-api/). Model credentials stay on that server. The host must also provide an API and updates for its task data. Here, React and the tools share an in-page Zustand store. On a server, tools should use the host’s server-side task operations, while the React board uses the host’s API to read and change tasks. Familiar’s conversation events do not synchronise that data.
